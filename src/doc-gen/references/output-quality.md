# 输出质量规则

## 路径与格式

- 所有路径使用相对仓库根目录的正斜杠路径。
- Markdown 标题层级稳定，不跳级。
- 代码块必须添加语言标识。
- 不复制大段源码，只保留关键签名、极短调用示例或路径定位。

## YAML Frontmatter

- 新生成文档必须包含 YAML frontmatter。
- `doc_type` 固定为 `ai-module-spec`。
- `audience` 固定为 `ai`。
- `read_mode` 固定为 `progressive`。
- 必须包含 `read_order.quick_edit`、`read_order.architecture`、`read_order.debugging`。
- YAML 只承担导航和索引职责，不写长篇解释。

## 长度控制

- 简单模块：YAML 25-50 行，正文 150-300 行。
- 标准模块：YAML 40-80 行，正文 300-600 行。
- 复杂模块：YAML 60-120 行，正文 600-900 行。
- 正文可以放宽，但章节必须可跳读。

## 事实来源

- 代码可确认的内容可以直接写入正文。
- 测试覆盖的内容使用 `[测试验证]` 标注。
- 只能从命名、目录或上下文推断的内容使用 `[推断]` 标注。
- 业务意图不明确、测试缺失或调用链不完整的内容写入 `待确认项`。
- 不得把推断内容写成确定业务规则。

## AI 快速接手

- 正文前半部分必须包含 `AI 快速接手`。
- 该章节必须列出修改前必读文件、常见修改入口、风险摘要和推荐验证命令。
- 正文前半部分必须包含 `AI 修改守则`。

## 测试与验证

- `已验证行为` 必须同时包含测试文件、验证命令和测试证明点。
- 如果没有测试，必须在 `待确认项` 说明缺口。
- 推荐验证命令优先使用项目已有 pnpm 命令。

## 影响范围

- 能从 import、测试、路由、调用关系确认的下游消费者写入 `confirmed`。
- 只能推断的下游消费者写入 `inferred`。
- 无法确认时不要编造影响范围。
- 修改影响矩阵必须包含修改类型、影响文件、风险和建议验证。

## 问题排查路径

- 简单模块可以没有具体排查步骤；如果 YAML `read_order.debugging` 包含 `问题排查路径`，正文保留短章节说明未生成原因并指向 `待确认项`。
- 标准和复杂模块只有在能从代码、测试或调用链确认时才生成排查路径。
- 如果排查路径不可靠，不写步骤，改在 `待确认项` 说明。

## Mermaid

- 简单模块默认不用 Mermaid。
- 标准模块在关系明确时可使用一个 Mermaid 图。
- 复杂模块可使用 Mermaid 表达依赖关系、数据流、状态流或请求链路。
- Mermaid 图下必须提供 2-5 条文字解释。
- 不确定关系不得画进图。

## 旧文档迁移

- 新文档默认使用新格式。
- 旧文档只有在用户明确要求更新、重写、升级格式或按新模板整理时迁移。
- 普通追加补充时尊重原文档结构。
- 迁移结果必须在最终报告中说明。

## 输出前检查

- 检查生成文档路径、索引路径、模块类型、复杂度和未处理事项。
- 检查 YAML 是否可解析。
- 检查 `待确认项` 是否收集了不可靠推断。
- 检查没有大段源码复制。
