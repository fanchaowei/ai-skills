# 已有模块文档增量更新

## 输入变化集

优先读取用户给出的 diff、当前工作树差异或明确的变更文件清单。只分析已确认模块边界内的变化，以及目标模块真实使用的直接公共依赖契约变化；调用方变化始终排除。

## 路径与 symbol 提取

- 从 diff 提取仓库根相对正斜杠路径、增删状态和相关 symbol。
- 将改名视为旧路径删除与新路径新增；即使行为不变也必须更新导航。
- 对每个变化标记 `owned`、`direct-public-dependency`、`shared`、`caller` 或 `excluded`。
- 证据不足时先执行边界确认门禁，不猜测章节影响。

## 变化到章节映射

| 变化类型 | 必查索引与章节 |
| --- | --- |
| 新增 | `feature_index`、功能目录、当前公开契约、直接依赖、验证入口 |
| 修改 | 对应功能事实链、局部不变量、诊断、数据流、验证入口 |
| 删除 | 失效 `feature_index`、功能章节、公开契约、删除边界和所有失效引用 |
| 公开契约变化 | `detail_sections.contract`、相关功能、直接公共依赖和验证范围 |
| 诊断变化 | 症状索引、第一检查点、稳定信号和下一验证入口 |
| 依赖变化 | 直接公共依赖、模块内吸收位置、相关功能与扩大验证条件 |
| Bug 修复 | 症状、状态责任、功能不变量；若只是恢复已记录契约，可无需修改模块文档 |
| 内部重构 | 路径和 symbol；稳定事实与导航均未变化时可无需修改模块文档 |

## 最小读取范围

1. 读取 YAML 中与变化路径或功能域相关的 `feature_index` 和 `detail_sections`。
2. 读取受影响功能章节、公开契约和必要按需章节。
3. 读取验证入口与文档维护信息。
4. 仅在判断交叉引用或导航一致性时读取其他小节，不默认通读全文。

## 最小写入范围

- 只修改受影响的 YAML entry、正文小节和必要交叉引用。
- 保持无关章节原文、顺序和语义不变。
- 删除功能时彻底移除失效路径、symbol、契约和验证引用。
- 更新完成后统一刷新 `last_updated`，不追加变更历史或提交记录。

## 无需更新判定

“无需修改模块文档”只判断当前代码变化是否产生新的稳定模块事实或导航增量，不代表任何任务都可原样交付已有文档。允许作出该判定的条件：

1. 纯内部重构没有改变真实入口、路径或 symbol、公开契约、稳定状态语义、依赖契约、诊断入口或验证入口。
2. Bug 修复只是让实现重新符合文档已记录的当前契约，且导航仍有效。

结论必须说明已核对的变化和导航范围。路径或 symbol 改名时，即使行为不变，也必须更新导航。

## 任务范围与文件写入

- 用户或执行流程只要求判断、回答，未要求产出、写入或维护完整模块文档时，结论为无需更新就只报告结论，不创建、覆盖或升级文档文件。
- 任务同时要求产出、写入或维护完整模块文档时，代码变化判定与格式合规检查分开执行：已有 v1/v2 文档即使没有事实或导航增量，也必须迁移为 v3。
- 完成报告必须分别说明“本次代码变化无需事实更新”和“文档仅进行了 v1/v2 到 v3 迁移”；不得把格式迁移冒充为该 diff 引起的事实更新。
- 已有 v3 文档没有事实或导航增量时保持文件字节不变；若交付机制必须另存完整副本，正文、章节和维护元数据也必须原样保留，不借机重写或刷新 `last_updated`。

## v1/v2 到 v3 的结构迁移

- 用户要求更新、重写、升级、按新模板整理，或任务要求产出、写入、维护完整模块文档时，将 v1/v2 文档升级为 v3。
- 首次 v3 升级允许结构性重写，以建立 `feature_index`、固定 `detail_sections` 和当前事实边界。
- 不双写旧字段与 v3 字段，不保留阶段记录和历史验证状态。
- 升级后进入普通 v3 增量规则，后续更新优先局部修改。

## 更新后全局检查

- 所有 `feature_index.entry` 路径和可选 symbol 可达。
- 所有 `body_section` 与 `detail_sections` 标题可达。
- 可选 key 与正文同步出现或同步删除。
- 不含 caller、历史提交、瞬时验证状态或失效引用。
- 无关章节未被重写。
