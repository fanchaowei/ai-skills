# 模块事实模型

## 文件角色

为每个候选文件分配且只分配一个角色：

| 角色 | 定义 | 文档处理 |
| --- | --- | --- |
| `owned` | 对目标模块具有专属性和强实现耦合，并与模块共同演进 | 记录当前模块事实 |
| `direct-public-dependency` | 目标模块真实 import、类型引用或调用的外部公开契约 | 只记录实际使用的最小公开契约 |
| `shared` | 被多个模块共同依赖，不能归目标模块所有 | 仅作为直接公共依赖时记录最小契约 |
| `caller` | 通过目标模块公开契约使用目标模块的调用方 | 无条件排除 |
| `excluded` | 仅因命名、目录或搜索命中出现，或与模块无直接事实关系 | 排除 |

物理目录不是硬边界。目录外的专属 store、composable、service、adapter、类型、样式或测试只有同时具备专属性和强实现耦合证据时才可判为 `owned`；目录内的共享文件也可判为 `shared`。

## 边界确认门禁

出现以下任一情况时，暂停并等待用户确认：

- 候选文件可能同时属于 `owned` 与 `shared`，但缺少真实引用或共同演进证据。
- 用户给出的范围与代码依赖方向冲突。
- 目标目录包含多个相互独立的功能所有者。
- 只有读取调用方实现才能解释目标模块行为。

暂停时只输出候选边界表，包含路径、候选角色、证据和疑点。确认前不得生成最终模块文档、YAML 或正文。`caller` 没有例外，不能因耦合、唯一使用方或排障便利而纳入。

## 事实来源用途

| 来源 | 可证明 | 不可证明 |
| --- | --- | --- |
| 生产代码 | 当前实现、真实 symbol、依赖方向、状态转换和公开结果 | 未来计划、业务目标、测试已通过 |
| 模块内部测试 | 预期行为、覆盖范围和稳定验证入口 | 当前实现必然符合预期、本次执行结果 |
| 用户说明、AGENTS.md | 边界、术语、维护约束和明确业务规则 | 代码中不存在的当前实现 |
| 旧模块文档 | 搜索线索和待核对事实 | 当前事实 |
| Git 历史、设计或实施文档 | 必要的兼容背景 | 阶段记录、提交列表和瞬时状态 |
| 推断 | 形成待确认问题 | 确定事实 |

测试不得创造实现事实。旧文档只作线索。推断必须保持为待确认问题，不能改写成当前契约。

## 核心功能域

- 只为稳定业务能力建立核心功能域，最多 8 个。
- 超过 8 个时按稳定业务领域合并，不按文件数量截断。
- 次要转发或纯实现细节可以留在正文功能目录，不进入 `feature_index`。
- 功能名称使用当前能力和真实 symbol，不使用阶段编号或虚构业务名。

## 最小完整事实链

每个核心功能域至少追踪：

`真实入口 → 编排或状态 → 数据转换 → 直接公共依赖或模块公开结果 → 验证入口`

链路节点必须映射到真实仓库根相对 `路径#symbol`。只记录理解职责、修改边界和故障边界所需的最短链路，不向调用方向扩展，也不复制 provider 内部实现。

## 直接公共依赖

从目标模块真实 import、类型引用或调用出发，记录 provider、公开 symbol、目标模块实际使用的输入输出、必要语义和模块内使用入口。缺少 provider 文档时读取公开声明形成最小契约；不得读取或复制 provider 内部实现来扩充目标模块文档。

## 模块内事实冲突

只处理已确认模块边界内的冲突。实现、模块测试、用户上下文或旧文档不一致时，生成按需章节“模块内事实冲突”，记录冲突来源、内容和待确认事项。冲突未解决前不得把任一版本写成确定事实。

## 禁止写入的内容

- 调用方的实现、状态、测试、回退逻辑、修改计划或排障步骤。
- 历史阶段、提交列表、实施进度和兼容迁移过程记录。
- `passed`、`failed`、`not_run`、`blocked` 或人工待验收等瞬时验证状态。
- 测试期望补全出的实现、旧文档遗留事实或无证据推断。
- provider 内部实现、完整上游契约或与目标模块无真实引用的相似能力。
