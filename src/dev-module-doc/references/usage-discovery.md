# Usage Example Guidance

## 目标

基于模块的公开导出、真实组件契约和显式类型，为每项开发者可使用的公开功能整理接入说明和最小示例。示例用于帮助开发人员理解接入方式，不展示仓库中的真实使用方。

## 示例来源

优先依据：

- 公开导出的函数、类型、常量、组件名。
- `props`、`emits`、`slots`、`defineExpose` 等组件契约。
- store id、state、getters、actions。
- composable 函数签名和返回值。
- service/API 方法签名、请求参数和响应类型。

## 覆盖对应关系

1. 从公开契约整理功能清单，以开发者能完成的操作或接入场景为单位，包括公开配置、组件能力和状态操作，不只统计导出函数名。
2. 为每项功能记录对应的公开入口、`## 使用方式` 下的小节或示例，以及必要前置条件。该对应关系用于写作和自检，不强制额外发布一张大表。
3. 一组需要协作使用的公开入口可以共用一个完整示例；类型、常量和参数可以在相关示例中体现，不必各自成为独立用法。
4. 逐项检查读者能否据此知道如何调用、传参和处理结果；仅列名称、签名或功能描述不能算作使用示例。

## 增量更新

- 对照当前公开契约与已有文档，并结合可用 diff 或用户说明确认新增、变更、移除的功能；已有文档不能代替当前代码事实。
- 新增功能补充功能清单，并在前部 `## 使用方式` 中增加或扩展对应示例。已有正确用法继续保留，避免更新新功能时遗漏原有功能。
- 公开参数、返回值或配置约定变化时，同步修正相关用法；已移除的入口清理失效示例和导航。
- 新用法已经散落在后面的独立章节时，将最小接入路径归入 `## 使用方式`；其他章节保留必要详解，避免重复粘贴整段示例。
- 无法生成可靠示例的功能，在使用方式中明确说明缺少的契约或前置条件，并在交付时报告；不能将其标记为已覆盖。

## 示例要求

- 使用真实存在的导出和类型。
- 保持最小、可参考，不扩展成完整业务代码。
- 配置、调用、回调或清理共同构成用法时，展示必要关系；只覆盖旧主流程而遗漏新增公开能力不算完成。
- 不编写或引用“真实使用方示例”。
- 不为了示例专门搜索仓库调用方。
- 当公开契约不足以生成可靠示例时，说明缺少的信息，不编造参数、返回值或调用链。
