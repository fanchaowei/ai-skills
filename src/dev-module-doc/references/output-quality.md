# Output Quality

## 完成前自检

生成结束前检查：

- 文档落点是否正确。
- `docs/modules/*.md` 的文件名是否使用简体中文。
- `docs/modules/*.md` 的正文是否使用简体中文。
- 功能清单是否与当前公开契约一致。
- `## 使用方式` 是否位于文档前部、公开输入输出和设计逻辑之前。
- 是否逐项核对“公开功能 → 使用小节/示例”，每项功能都有接入说明和最小示例，或明确报告尚缺的契约信息。
- 新增或变更公开功能是否已经纳入该章节，而非只追加到文末专题。
- 增量更新是否保留原有有效用法、修正变化的契约并清理已移除入口的示例。
- 示例是否基于真实导出和类型，包含该场景所需的前置配置、调用及结果处理。
- 是否列出公开输入。
- 是否列出公开输出。
- 是否列出主要依赖。
- 是否包含常见修改入口。
- 是否说明注意事项。
- 是否更新 `docs/README.md`。

覆盖按公开功能或使用场景判断，不按代码块数量判断。多个相关功能共用一个完整示例可以通过；只有签名列表、旧主流程示例，或仅在其他章节提供新增功能用法，均不能视为覆盖完整。不得为满足篇幅建议省略公开功能。

## 禁止行为

- 不编造不存在的 API。
- 不编造不存在的类型。
- 不编造不存在的参数或返回值。
- 不编写或引用“真实使用方示例”。
- 不为寻找示例而专门搜索仓库调用方。
- 不把内部实现写成完整代码导读。
- 不把文档写入 `claudedocs/`。
- 不在 `docs/modules/` 下生成英文 slug、camelCase 或 PascalCase 文件名，除非用户明确指定。
- 不要求 Vue 2.7 项目支持 Vuex。

## 最终报告

最终回复包含：

- 模块文档路径。
- 索引路径。
- 模块类型。
- 新增或变更功能的用法覆盖情况；存在缺口时明确列出，不能宣称文档已完整覆盖。
- 无法自动确认的信息。
