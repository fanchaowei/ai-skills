# Document Template

## 输出语言

`docs/modules/*.md` 使用简体中文文件名和简体中文正文，采用简洁直接的工程说明风格。`docs/README.md` 只作为索引维护入口，不适用模块正文语言要求。

## 默认结构

`## 使用方式` 必须位于公开输入、公开输出和设计逻辑之前。模块概览与简短功能清单可以放在它前面；新增功能的用法也归入此章节，不在文末另设唯一的用法入口。

```markdown
# 中文模块名

## 模块概览

一句话说明模块职责。

## 功能清单

- 功能 1
- 功能 2

## 使用方式

按公开功能或使用场景组织说明和最小示例，覆盖功能清单中的每项公开能力。单一功能可以直接展示示例，多项能力使用三级标题组织；需要初始化、配置或清理的场景应包含必要步骤。

## 公开输入

| 名称 | 类型 | 必填 | 说明 |
|------|------|------|------|

## 公开输出

| 名称 | 类型 | 说明 |
|------|------|------|

## 主要依赖

| 依赖 | 用途 |
|------|------|

## 设计逻辑

只说明对使用和修改有帮助的主流程，不展开所有内部私有函数。

## 常见修改入口

| 修改目标 | 入口位置 | 说明 |
|----------|----------|------|

## 注意事项

- 使用限制。
- 已知边界。
- 错误处理约定。
- 不确定点。
```

## 示例要求

每项公开功能都必须能在 `## 使用方式` 中找到对应的接入说明和最小示例。相关功能可以组合在一个完整场景中展示，不要求每个函数、参数或类型各占一个代码块。

示例必须基于真实导出或真实组件契约，不编写“真实使用方示例”，也不要为了示例专门搜索或引用仓库中的调用方。输入输出、设计逻辑和注意事项可以补充细节或链接到用法，但不能替代前部的使用说明。

## 长度控制

默认控制在 2-4 屏；这是篇幅建议，不能以此省略公开功能的用法。优先合并共同前置步骤和相关场景，复杂模块可以略长，但不要写成完整源码导读。
